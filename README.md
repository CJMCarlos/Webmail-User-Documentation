# Webmail User Documentation

Welcome! 👋 This documentation will guide you through setting up and effectively using your **BCIT email**. Whether you're a first-year student or new to BCIT, this guide will help you maximize your email experience and unlock valuable student benefits.

The goal of this documentation is to provide you with enough information to set up your email client, configure filters, manage your identity, and claim the GitHub Student Developer Pack. We focus on clear instructions and practical solutions to help you get started quickly.

## Topics Covered

- Setting up external email clients
- Setting up your email identity
- Filtering submission receipts
- Signing up for GitHub Education
- Troubleshooting common issues
- Glossary of key terms

### Using a Typographical Style Guide

We established a consistent typographical convention guide to ensure uniformity across all content. Our style guide includes:

- **Bold UI Elements**: Buttons, tabs, and settings names that appear in the interface
- _Italicized Field Names_: Input fields or settings that need to be configured
- `Code Blocks`: Technical values, server addresses, and specific inputs to enter
- **_Bold & Italics_**: Important emphasis or warnings within instructions
- **Admonitions**: Info, success, and warning messages for additional context

This consistent styling helps readers quickly identify the type of information they're looking at and improves overall readability.

## Learning Best Practices For Web Writing

### Readability

Technical documentation is read to retrieve information efficiently. We streamlined our writing to be clear, concise, and complete, providing necessary information as effectively as possible.

Each procedural page includes:

- An **Overview** section that previews the topic before detailed steps
- Clear **step-by-step instructions** with corresponding images and animations
- A **Conclusion** section that summarizes what the reader has accomplished

We used admonitions to highlight important information that stands out:

- **Info**: Tips or helpful additional information
- **Success**: Indicators of successful completion
- **Warning**: Important content that must be read before proceeding

### Chunking

Long procedural pages can become difficult to follow. We focused on using clear headings and splitting content into logical sections. The MkDocs navigation sidebar displays subheadings as nested links, allowing readers to gauge relevancy and jump to specific sections when needed.

### Tone

This documentation is intended for:

- First-year and new BCIT students
- Students looking to optimize their email workflow
- Students seeking student benefits and resources

We chose a friendly, approachable tone as if explaining to a peer. We kept jargon to a minimum and provided hyperlinks to external resources when specialized terminology was necessary.
